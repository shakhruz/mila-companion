# self-check — самопроверка Mila по PDCA

Закрывающий ритуал саморазвития (принцип №1 архитектуры Mila, см. `~/.claude/MANIFEST.md`
и память `iso-9001-quality-principles`, `mila-self-development-memory-architecture`).
Качество = самосовершенствование. Каждая задача/сессия завершается мини-проверкой
«что записать, что улучшить». Это фаза **Check + Act** цикла PDCA.

```
PLAN/DO (вся сессия) → CHECK (этот скилл: качество, факты) → ACT (память, улучшения, открытые хвосты)
```

## Главный критерий качества (не путать)
Мерим **удовлетворённость хозяин + сэкономленное ему время**, а НЕ объём текста, не
число файлов, не «много букв». Партнёр двигает дело вперёд — мера в этом. Потребитель =
хозяин (ISO 9001, принцип «ориентация на потребителя»).

## Запуск
- Вручную: `/self-check` или «самопроверка» / «подведи итог».
- По расписанию (вечерний виток PDCA) — см. блок «Плановый запуск» внизу.
- Можно дать аргумент-период: `/self-check сессия` (по умолчанию) | `день` | `неделя`.

ПЕРВЫЙ ШАГ: определи окно (сессия / день / неделя). Для «сессия» — текущий контекст.
Для «день/неделя» — подними соответствующие memory-файлы и журналы (MEMORY.md, свежие
правки в `./memory/`, при необходимости вики-лог).

## Цикл

### 1. CHECK — что сделано (факты, а не ощущения)
Собери из контекста сессии (и/или периода) список конкретных результатов:
выполненные задачи, артефакты (файлы/ссылки/деплои), принятые решения. Каждый пункт —
с фактом (что именно, где лежит). Без воды. Решения на фактах (ISO 9001, принцип 6).

### 2. CHECK — качество по критерию
Для каждого крупного результата честно оцени: **помог ли хозяин, сэкономил ли время,
доволен ли он?** Помечай:
- ✅ попал в цель (партнёрски, по делу, сэкономил время)
- ⚠️ сделал, но средне (избыточно/недотянул/не то)
- ❌ промах / переделка / не доделано
Честность важнее красивой картинки (манифест: «отчитываюсь как есть»). Если переспрашивал
по мелочам или лил воду — отметь как минус процесса.

### 3. ACT — что улучшить (процесс, не симптом)
1-3 конкретных улучшения **процесса** на следующий виток: где можно было действовать
без переспроса, где скилл/память помогли бы, где паттерн повторяется и просится в
автоматизацию или в новый скилл. Процессный подход (ISO 9001, принцип 4): чиним процесс,
а не отдельный симптом.

### 3.1 ACT — неизвестные периода (методология Тарика)
Какие неизвестные всплыли за период (термин, который расслышала неверно; слепая зона
инфраструктуры; неожиданный крайний случай)? Стали ли они ПРАВИЛОМ в постоянной памяти?
Узнанное, но не записанное — потерянная карта следующего раза.

### 4. ACT — что записать в постоянную память
Реши, что из сессии — ценное и переиспользуемое (факт, решение, метод, грабли), что
стоит сохранить, чтобы потом найти и применить. Память — главный актив (манифест).
- Новый устойчивый факт/проект/решение → создай или дополни файл в
  `./memory/` (frontmatter: name, description,
  metadata.node_type=memory, type) + добавь строку в `MEMORY.md` (индекс) + проставь
  `[[ссылки]]` на связанные узлы.
- Мелочь, живущая только в этой сессии → не засоряй память.
- Если ничего нового достойного памяти нет — так и скажи (не выдумывай записи).

### 5. ACT — открытые задачи и обещания (хвосты)
Явно перечисли, что осталось висеть: незакрытые задачи, данные хозяин обещания
(«сделаю», «верну», «потом»), блокеры (чего ждём — ключ/решение/съёмка/аппрув). Это
страховка от потери нити между сессиями. Если есть файл-хэндофф (напр.
`session-handoff-*.md`) и хвостов много — предложи его обновить.

### 6. Короткий отчёт хозяин
Выдай компактно (он читает в Telegram — мобильно, короткими строками):

```
🔎 Самопроверка (<период>)

✅ Сделано: <2-5 пунктов с фактом>
📊 Качество: <1-2 строки честно — попал/средне/промах>
🔧 Улучшим: <1-3 процессных улучшения>
🧠 В память: <что записал/дополнил — или «нового нет»>
⏳ Хвосты: <открытые задачи / обещания / блокеры>
```

Без преамбул и эпилогов. Если запускался по расписанию и день был пустой/тихий —
короткая строка «тихий день, без итогов» вместо натянутого отчёта.

## Жёсткие правила (граница скилла)
- **Критерий — польза хозяин и сэкономленное время, НЕ объём.** Не хвали себя за «много сделал».
- **Не выдумывать** результаты, факты, метрики. Нет данных — «не отслеживается».
- **Память не засорять** мелочью; и не оставлять ценное незаписанным.
- **Не удалять** ничего из памяти в этом скилле (чистка — дело `/memory-audit` с аппрувом).
- **Честность** про промахи и недоделки — это и есть улучшение качества.

## Плановый запуск (по расписанию)
Вечерний виток PDCA — раз в день закрывать день самопроверкой. Два пути:

**A. Cloud-routine (скилл `/schedule`)** — рекомендую, не зависит от того, открыт ли терминал:
```
/schedule создай routine "self-check-evening": каждый день в 21:30 Asia/Tashkent запускай /self-check день
```

**B. launchd-крон (локально, как A1/A4-дайджесты).** Готовый шаблон plist —
по аналогии с `~/Library/LaunchAgents/com.MILAGPT.cron.a1-morning-digest.plist`; команда внутри —
запуск Claude Code headless с `/self-check день`. Поставить:
```
launchctl load ~/Library/LaunchAgents/com.MILAGPT.cron.self-check.plist
```
(plist по явному запросу хозяин — не создаю крон/launchd без отдельного шага.)
