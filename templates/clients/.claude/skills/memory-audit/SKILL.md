# memory-audit — профилактика постоянной памяти

Память — главный актив Mila (манифест). Модель меняется за вечер; постоянная память —
то, чем мы владеем. Поэтому её надо профилактически чистить и чинить, а не реагировать,
когда сломалось. Это вектор саморазвития «профилактика/анализ памяти» и риск-мышление
ISO 9001 (см. `~/.claude/MANIFEST.md`, память `iso-9001-quality-principles`,
`mila-self-development-memory-architecture`).

```
СКАН → ДИАГНОСТИКА (груз/дубли/битые ссылки/вне индекса/устарело) → ОТЧЁТ-РЕКОМЕНДАЦИИ → (аппрув) ПРАВКИ
```

Корень памяти: `MEM=./memory/`
Индекс: `$MEM/MEMORY.md`

## Запуск
- Вручную: `/memory-audit` или «аудит памяти» / «проверь память».
- По расписанию (профилактика раз в неделю) — см. блок внизу.
- Аргумент-режим: `/memory-audit` (полный) | `/memory-audit ссылки` (только битые `[[ссылки]]`) |
  `/memory-audit индекс` (только рассинхрон с MEMORY.md).

## Цикл

### 1. Скан инвентаря
- `ls` файлов `$MEM/*.md`, их размеры и даты модификации.
- Прочитай `MEMORY.md` целиком — это индекс-карта.
- Для диагностики читай файлы прицельно (frontmatter + первые строки + `[[ссылки]]`),
  не вытягивай всё подряд без нужды.

### 2. Мёртвый груз (кандидаты в архив)
Помечай файлы, где задача **выполнена / событие прошло / план реализован** и ценность
уже исторична:
- frontmatter/тело со статусом «ВЫПОЛНЕНО», «done», «снесён», «decommission»;
- дата-привязка в прошлом (`*-2026-06-NN`) + контент про разовое событие;
- проект, который явно завершён или заброшен (сверь по тону MEMORY.md).
Это **кандидаты в архив**, не на удаление. Предложи перенос в `$MEM/_archive/`
(создать папку при аппруве) с сохранением `[[ссылок]]`.

### 3. Дубли и пересечения
Найди файлы про одно и то же (по name/description/теме): несколько заметок об одном
проекте/решении, которые стоит **слить** в один узел, оставив редиректную строку. Не
сливай автоматически — предложи, какой основной, какие вливаются.

### 4. Битые `[[ссылки]]`
Прогон по всем файлам: собери каждую `[[wikilink]]`, проверь, существует ли
`$MEM/<link>.md` (или известный внешний узел, напр. в `./memory`). Список «битых»:
ссылка → файл-источник → вероятная причина (опечатка / файл переименован / файл в вики /
узел ещё не создан). Предложи: починить имя, создать заглушку-узел, или снять ссылку.

Быстрый сбор кандидатов (грубо, для ориентира — точную сверку делай чтением):
```
grep -rho '\[\[[^]]*\]\]' "$MEM" | sort -u
```
Затем для каждого имени проверь наличие `$MEM/<имя>.md`.

### 5. Файлы вне индекса MEMORY.md
Сопоставь список `*.md` на диске со ссылками в `MEMORY.md`. Файлы, на которые индекс
**не ссылается** — «осиротевшие»: либо дописать строку в индекс, либо это и есть мёртвый
груз. Перечисли их отдельно.

### 6. Что пора актуализировать
Помечай узлы, где факты **устарели** относительно более свежих файлов (напр. план «ждём
X», а в свежем файле X уже сделан; старый статус проекта). Предложи, что дописать/поправить,
со ссылкой на свежий узел-источник. Решения на фактах (ISO 9001, принцип 6).

### 7. Отчёт-рекомендации хозяин
Компактно (он читает в Telegram), сгруппировано, с конкретными действиями:

```
🧹 Аудит памяти (<N файлов>)

🗄️ В архив (выполнено/прошло): <список файлов + 1-словная причина>
🔗 Битые ссылки (<K>): <ссылка → источник → фикс>
👥 Дубли/слить: <A+B → основной>
📍 Вне индекса (<M>): <файлы → дописать в MEMORY.md / в архив>
🔄 Актуализировать: <узел → что устарело → свежий источник>

Рекомендую начать с: <1-2 самых ценных действия>.
Сказать «делай <что>» — выполню (с аппрувом).
```

### 8. Правки — только по аппруву
Не трогай память, пока хозяин не подтвердит конкретное действие. После аппрува:
- архив → `git mv`/перенос в `$MEM/_archive/` + строка-редирект в MEMORY.md;
- фикс ссылок → точечный `Edit`;
- слияние → перенос контента в основной узел, заглушка-редирект в дубль;
- индекс → дописать строки в MEMORY.md.
Каждое — отдельной атомарной правкой; отчитайся, что сделано.

## Жёсткие правила (граница скилла)
- **НЕ удалять / НЕ архивировать / НЕ сливать без явного аппрува хозяин.** Скилл по
  умолчанию только диагностирует и рекомендует.
- **Архив ≠ удаление.** Перенос в `_archive/`, ничего не теряем безвозвратно.
- **Не выдумывать** битые ссылки/дубли — сверяй чтением, а не догадкой.
- **Сохранять прослеживаемость** (ISO 9001): при переносе/слиянии оставляй редирект-строку.
- Профилактика, а не реакция — гоняй регулярно, а не когда уже сломалось.

## Плановый запуск (по расписанию)
Профилактический виток — раз в неделю. Два пути:

**A. Cloud-routine (скилл `/schedule`)** — рекомендую:
```
/schedule создай routine "memory-audit-weekly": каждое воскресенье в 20:00 Asia/Tashkent запускай /memory-audit и пришли мне отчёт
```

**B. launchd-крон (локально).** Шаблон plist по аналогии с
`~/Library/LaunchAgents/com.MILAGPT.cron.a1-morning-digest.plist`, команда внутри — headless
Claude Code с `/memory-audit`. Поставить:
```
launchctl load ~/Library/LaunchAgents/com.MILAGPT.cron.memory-audit.plist
```
(plist — по явному запросу хозяин; крон/launchd сам не завожу.)
